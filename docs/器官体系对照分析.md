# 幽匿手写方案与设计稿的对照分析

本文对比 [vanillaShulk修改方案.md](/home/kuzuanpa/projects/1.20.1/theOrgans/vanillaShulk修改方案.md:1) 与 [design-vanilla-sculk.txt](/home/kuzuanpa/projects/1.20.1/theOrgans/organs/vanillaSculk/design-vanilla-sculk.txt:1)，说明手写方案如何从设计稿里做选择和取舍，再以沙漠、地狱两套体系作为反例，回看其他器官体系存在的问题。

## 一、两份文档的关系

`design-vanilla-sculk.txt` 是**上游概念稿**，负责回答“幽匿体系是什么”：来源身份（原版深暗 + 古城 + Otherside）、四大状态（静默活性、回响储能、震感标记、异界适应）、25 个器官的意象与多条“方向性”效果、以及 6 条联动链。它偏“说明意图”，一个器官经常同时给好几个候选方向（例如伏听肺叶同时给“潜行续航 + max_mana + 施法稳定”）。

`vanillaShulk修改方案.md` 是**下游取舍稿**，负责回答“每个器官最后到底做成什么”。它假定主场条件和基础面板不变，只做一件事：把每个器官的功能特效收敛成一句话可描述、单触发可实现的词条，并删除其余“多余特效”。它还把设计稿里大量分散的“异界/结构/搜刮”语义压缩进少量主场或资源效果，并新增 `监守者核心` 作为整套体系的主动落点。

所以两篇文档不是“新旧版本”的关系，而是**“蓝图 → 施工图”的关系**：设计稿定了身份、方向和联动愿景，手写方案定每个槽位具体装什么、花哪个资源、触发什么事件。

## 二、手写方案对效果的选取与取舍

### 保留的

- **来源与主场**：幽暗维度 / 幽暗群系 / 古城附近的判定不变，保持“幽匿”身份不稀释。
- **基础面板属性**：器官的基本属性（心力、魔力、护甲等）保持不变，作为耐打/续航底盘。
- **器官名与槽位**：基本沿用设计稿的 25 个器官，不为了精简而砍来源宽度。
- **核心资源与标记**：保留了设计稿最关键的“回响储能”和“震感标记”两个状态，并把它们变成真正的经济闭环。

### 删除 / 收敛的

- **删除每器官的多候选效果**：设计稿里“也提供 max_mana”“可追加减速/虚弱/标记”这类候选项，被统一改成各干一件事。例如伏听肺叶不再同时给蓝量，监守骨板只给护甲。
- **收敛四大状态为两个可交互状态**：静默活性被退化成“潜行 + 主场”的触发条件；异界适应被并入“主场”这一条件。真正可积累、可消耗、可互动的只剩下回响储能和标记。
- **压缩结构搜刮与异界扩展语义**：设计稿重笔墨的“Ancient Temple / Otherside 怪物适应 / 搜刮链”，在方案里只剩少量主场续航（异界浮膜、深层囊室）和资源件（幽壳脾囊、古庙裂罐手），没有为了“容纳 Deeper and Darker”再堆一堆零碎机制。

### 新增的

- **`监守者核心`（warden_core）**：解剖监守者获得，主动消耗一半回响储能，释放 `irons_spellbooks:sonic_boom`，等级 = 消耗储能 / 5。它给整套“只进不出”的防御式资源一个真实出口。

### 取舍判定：同一行为只保留一个落点

以“标记”为例，设计稿把标记机会散在耳蜗、副脑、臂束、喉囊、前额等多个器官上。手写方案把链条切成明确三段：

- 上标记：静默冠脑（概率标记发声目标）、潜脉臂束（近战上标记）、感器喉囊（近身上标记）。
- 增标记率：回声耳蜗。
- 吃标记：传感副脑（幽匿法术对标记生物增伤并消耗储能）、缩声箭腺（远程对标记增伤）。

储能同理：回响心核给上限，谐振脊髓、传波前额、深层囊室负责攒，传导叉结、深心残瓣、古庙裂罐手、异渊猎膜负责把储能转成蓝、血、幸运、生命上限，最后监守者核心一次性花出去。这样每个器官在循环里都有唯一生态位，删掉任意一个都会有明显缺口。

## 三、与设计稿的两处明显分歧

1. **“不要复刻 sonic boom”被打破**：设计稿明确写“不要真的复刻 Warden 的 sonic boom，用黑暗/发光/减速/虚弱/击退就够”。手写方案把它变成一个受储能解锁的**单个主动技能**。这个改动其实符合设计稿的另一个要求“不做纯 Warden cosplay”：只有监守者核心这一个主动爆发，其余器官仍走感知、潜行、黑暗路线，不整条路都是声波冲刺。
2. **异界/搜刮被大幅降权**：设计稿把 Otherside 适应、Ancient Temple 收益写得较厚，手写方案只保留了少量主场条件效果和资源件，属于主动牺牲“题材宽度”换取“每件好理解、好实现、好平衡”。

## 四、反例：沙漠与地狱体系存在的问题

对照 `organs/vanillaDesert/` 与 `organs/vanillaNether/` 的落地 JSON，能清楚看到手写方案要修的正是这两种常见病。

### 1. 同源内部模板复制（平庸化）

沙漠的 `quicksand_spleen`（流砂脾囊）和 `temple_scavenger_hand`（神殿拾荒手）几乎是同一份模板：都在 `mine` 事件里“+2 沙漠储能 + 一个 loot runtime”，然后丢同一张 `cactus / sand / gold_nugget` 掉落表；区别只是第二个多套了一层 `temple_online` 条件、多 roll 一次。名字、皮肤、触发条件不同，玩法却完全一样，属于“只靠文案区分”。

地狱的 `ash_spleen`（灰烬脾囊）也完全相同：`mine` / `kill` 触发，同一套 loot 结构。玩家装上两件只感到“又一颗掉材料的脾”，没有构筑差异。

### 2. 跨来源整块换皮（模板化）

沙漠与地狱很多器官的 JSON 骨架几乎逐字段相同，只是换了属性名称和掉落物品：

- `drought_liver`（沙漠肝）≈ `ember_liver`（地狱肝）：都是 `spell_cast(fire) → restore_mana + 回储能` + `max_mana/mana_regen` + `resonance_capacity`。
- `eclipse_crown`（日蚀冠脑）≈ `overload_crown`（过载冠脑）：都是 `cooldown_added(fire) → restore_mana` + `cooldown_reduction` + `fire_magic_resist`。
- `sandstone_breastplate` ≈ `obsidian_chest_cavity`：都在静态给护甲/韧性，在热区给生命或抗退，在主场给抗退。

这意味着“沙漠火系增幅”和“地狱火系增幅”没有玩法区别，只有数字和注释不同。

### 3. 单器官多效果堆叠（复杂化）

地狱 `sacrifice_spine_furnace`（献血脊炉）一个 JSON 里同时背着：静态护甲、抗退、`resonance_capacity`、受击回储能、命中回储能、献祭就绪时加攻击力、热区时加护甲韧性，共 7 类字段。玩家装一个器官要同时读“挨打、命中、献祭判定、环境判定”四条逻辑，偏离了“一个器官只说一件事”的复杂度边界。

沙漠 `drought_liver` 同样在单器官里叠了“火法施法回蓝、静态 max_mana/mana_regen、击杀回蓝、主场加蓝”四种效果。

### 4. 资源只进不出，缺少闭环

沙漠和地狱都定义了 `vanillaDesert_resonance` / `vanillaNether_resonance`，几乎所有器官都在 add，但看不到统一的消耗出口。储能要么变成纯计数、要么只换来一点属性，玩家攒着攒着就失去意义。这正好反衬出幽匿手写方案的价值：它有 `传感副脑 / 缩声箭腺 / 监守者核心` 这些明确的消费端，回响储能才是一条真正的循环，而不是堆在角落的日志。

## 五、结论

手写方案“大幅度改善”不是因为它把所有体系重做了一遍，而是因为它在设计稿之上做了一次**取舍级收敛**：

- 保留来源与面板，保证识别度；
- 每器官只留一个效果，瓦解同源堆叠与跨源换皮；
- 把多状态收敛成“储能 + 标记”两组可交互资源，并补齐明确消耗端；
- 用一个高辨识度的主动核心（监守者核心）做整套体系的落点，避免“又杂又平”。

这套取舍标准可以直接反向应用到沙漠、地狱等体系：先给每个来源定一个可进可出的核心资源，再让每个器官承担唯一的“产 / 耗 / 转化”角色，最后只保留少数组装型核心作用在主动能力上。
